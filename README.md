# code-coverage-experiment

A small [Astro](https://astro.build) app with unit tests and code coverage, used to experiment with running coverage in CI.

## Project structure

```
src/
  layouts/Layout.astro     Base HTML layout
  pages/index.astro        Home page
  utils/greeting.ts        Greeting helpers (unit tested)
  utils/counter.ts         Counter helpers (unit tested)
  utils/*.test.ts          Vitest unit tests
.github/workflows/test.yml CI workflow: tests + coverage
```

## Commands

| Command                 | Action                                        |
| ----------------------- | --------------------------------------------- |
| `npm install`           | Install dependencies                          |
| `npm run dev`           | Start the dev server at `localhost:4321`      |
| `npm run build`         | Build the production site to `./dist/`        |
| `npm test`              | Run unit tests once                           |
| `npm run analyse:sessions` | Analyse agent sessions via the agentsview CLI ([docs](scripts/session-analysis/README.md)) |
| `npm run test:watch`    | Run unit tests in watch mode                  |
| `npm run test:coverage` | Run unit tests and generate a coverage report |

## Testing & coverage

Tests are written with [Vitest](https://vitest.dev), wired into Astro via `getViteConfig()` in `vitest.config.ts`. Coverage is collected with the V8 provider (`@vitest/coverage-v8`) and reported as text, `lcov`, `html`, and `json-summary` into the `coverage/` directory. Coverage thresholds (80% for lines, statements, functions, and branches) fail the test run when not met.

## CI

The [`Tests` workflow](.github/workflows/test.yml) runs on pushes to every branch (except `gh-pages`) and on pull requests. It installs dependencies, runs the tests with coverage, renders a coverage report into the job summary, and uploads the full HTML/lcov coverage report as a build artifact.

The workflow also pushes the coverage report to the `gh-pages` branch — into `coverage/pr/<pr-number>` for pull requests and `coverage/branches/<branch-name>` (e.g. `coverage/branches/main`) for branch pushes — so each report is browsable via GitHub Pages once Pages is enabled for the repository (Settings → Pages → Deploy from a branch → `gh-pages`, `/ (root)`). The job summary links directly to the published report. Reports are published even when coverage thresholds fail, so failing runs can be inspected too.

The [`Coverage cleanup` workflow](.github/workflows/coverage-cleanup.yml) runs every Sunday (and on demand via `workflow_dispatch`) and prunes stale reports from `gh-pages` using [`scripts/cleanup-coverage.mjs`](scripts/cleanup-coverage.mjs): PR reports whose pull request was merged or closed more than a month ago, and branch reports (except `main`) whose branch was deleted or has not been pushed to for more than a month.

The job summary is generated by [`scripts/coverage-summary.mjs`](scripts/coverage-summary.mjs), which combines `coverage/coverage-summary.json` (totals and per-file percentages) with `coverage/lcov.info` (per-line hit counts) to show overall metrics with pass/fail status against the threshold, a per-file breakdown, and the uncovered line ranges for each file.
